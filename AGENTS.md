## Learned User Preferences

- **Issue Tracking And Remote Ownership:** GitHub issues are the current tracker for planning, progress, bugs, dependencies, and PR links. This overrides older Linear workflow instructions: the Linear skill is deprecated for routine work, and Linear updates or authentication are required only when explicitly requested. Preserve historical references; the active Swift migration is tracked in GitHub issue #782. GitHub remains the canonical remote until a separately requested migration to Tangled supplies a destination.
- Never create git commits or push to remote unless explicitly asked; when asked, stage only files changed for the current task, exclude unrelated edits, use a short conventional commit message, and push the active branch (often `main`).
- **Development Before Production:** Never introduce a Production change without the same change already present in Development. Backport Production fixes and removals before any release; verify current source parity and hosted Development behavior, including navigation and disabled features. Retired ingestion and its dependent feeds must stay retired in both environments. Required CI must reject Production PR patches absent from current `dev`.
- Prefer Swift Testing over XCTest for Swift tests (API, worker, packages, iOS) wherever the toolchain supports it.
- Prefer atomic source files: one type or view per file, grouped by folder—not large multi-type files.
- Prefer focused diffs: match existing project style, keep imports at the top, and avoid drive-by refactors or unsolicited docs. When adding Gateway/AppView routes, include matching Bruno requests and OpenAPI drift coverage. When a delegated or subagent outcome is already visible in the parent UI, do not restate its full contents unless asked or multi-task synthesis is needed; a brief confirmation is enough.
- When executing an attached implementation plan, do not edit the plan file; use existing to-dos, mark them `in_progress` while working, and avoid creating duplicate to-dos. For features with architectural or product tradeoffs, ask clarifying questions before choosing—do not cross decision points unilaterally.
- Use Title Case for product UI options, menu actions, and button labels unless existing copy clearly follows another pattern.
- Keep shared Web copy, navigation, and release labels in parity across Development and Production unless an intentional difference is documented. After a Production-only cherry-pick, check whether it needs a Development backport; audit shared UI labels before promotions.
- For web picker components (including shadcn/Base UI triggers and native `<select>` controls), reserve trailing text padding for the chevron and inset the icon from the border (for a 16px icon, use `pr-9` with `right-3`, or the design-system equivalent). Use an explicit chevron with `appearance-none` for native selects when browser arrows cannot be spaced reliably; keep the icon `pointer-events-none` and `aria-hidden`. Verify long labels, light/dark mode, and narrow widths so text never overlaps the icon or border.
- Use a confirmation step for destructive actions: iOS toolbar bulk read-state (e.g. "Mark All As Read") uses `.alert`—not `.confirmationDialog` (misaligned popover tail on iPhone); destructive deletes (saved links, folders) use `.confirmationDialog`. Add subtle `.sensoryFeedback`—`.success` on confirmed deletes/save/mark-all-read, `.impact` on pull-to-refresh.
- For native iOS work, prefer pure SwiftUI with idiomatic system chrome (do not force pixel-perfect mock clones); use UIKit only when SwiftUI cannot meet the requirement or there is a clear performance justification; conform to Swift 6 strict concurrency and Apple Human Interface Guidelines. Accessibility/HIG conformance passes must not change screen structure, stacks, columns, or navigation hierarchy—only modifiers, confirmations, haptics, and model memoization. Account actions such as Log Out belong in ProfileView, opened from the sidebar toolbar avatar—not a sidebar footer.
- The server runtime is Next.js Web plus the standalone Go AppView (`services/appview/cmd`, `services/appview/internal`). The native Apple app remains a client. Do not restore retired Swift backends or removed feature feeds. Issue #963 tracks the serverless migration; Development must precede Production.
- Keep web and iOS as thin consumers: sidebar/feed/folder/avatar/unread logic belongs in Gateway/AppView; do not duplicate discovery, RSS parsing, or projection rules per client. Prefer hard cutover to the server read path over long-lived client-side fallback merge logic. Initial `/read` load uses shared authenticated NDJSON `GET /v1/appview/bootstrap-stream` (Go AppView emits without buffering) for web and iOS—not a client-side sidebar/unread/entries waterfall. User-authored PDS repo writes (folders, subscriptions, prefs, entry read-state records) go direct to the viewer PDS via `PDSClient`/`Agent` with OAuth DPoP; a **401→200 nonce retry** on first write is normal RFC 9449 handshake, not auth failure. AppView mutations (read-mark, mark-all-read, enroll, sidebar resolve/refresh) use Gateway routes. Gateway PDS write-through cannot forward gateway-bound DPoP—supply **`X-ATProto-Upstream-DPoP`** for that path or write direct to PDS. **Mark-all-read** updates AppView read marks only (no server-side PDS `putRecord` loop); clients batch-sync scoped entries to PDS separately after bulk mark. Sidebar unread badges merge AppView baseline with local/PDS read state—not raw server counts alone; mark-all-read clears the full publication-scope badge optimistically (not merely cached-entry deltas). On web, prefetch other publications' entry lists in the background after sidebar load; prefer React Query sidebar projection cache as the bootstrap-stream merge baseline during in-flight loads; bootstrap `unreadCounts` NDJSON is sparse (omits zero-count publications)—apply with `replacePublicationIds` so omitted pubs zero stale badges; use `effectivePublicationUnreadCount` to reconcile server counts with cached feed rows and local read state. On web sidebar load, paint folder/publication section headers immediately with skeleton sub-rows beneath while stream data fills in. Persist sidebar folder/section expand in shared `the-social-wire.sidebar-expanded-keys.v1` per viewer DID (web localStorage, iOS storage).
- On web Base UI `Dialog` modals: reset form state on **open** (not close), keep `DialogContent` a direct child of `Dialog`, use `DialogClose` for Cancel.
- On web, prefer local IndexedDB image caching for publication avatars and entry thumbnails (`imageBlobCache`, `useCachedImageUrl`, `prefetchCachedImages`) so sidebar/feed images are not refetched on every render; dedupe concurrent fetches per URL and prefetch primary `thumbnailUrl` only (fallbacks load on `<img>` error). Display images in whatever format the publisher stored (PDS blob `mimeType` or HTTPS URL)—no client/server transcoding to WebP. Bluesky `cdn.bsky.app` URLs are not directly fetchable from the browser (CORS)—normalize or proxy before caching.

## Learned Workspace Facts

- The Next.js app lives in `apps/web`; common checks are `bun run turbo run build --filter=web...` and targeted `bun test` under `apps/web`. Tests colocate in each owning package (e.g. `apps/web/src/__tests__/`, `services/*/Tests/`, `packages/lexicons/__tests__/`)—not a root `tests/` folder; see `docs/test-plans/`. `bun run dev` runs `next dev --webpack` by default (`dev:turbo` uses Turbopack); keep `turbopack.root` in `next.config.ts` at the monorepo root (`../..`). Only one `next dev` per app directory—kill a stuck `next-server` before deleting `apps/web/.next/dev/lock`. Root metadata in `apps/web/src/app/layout.tsx` sets the default Open Graph/Twitter image to `/og/the-social-wire.png` with `metadataBase` from `NEXT_PUBLIC_SITE_URL`, else Railway's `RAILWAY_PUBLIC_DOMAIN`, else `https://thesocialwire.app`. The signed-in “My Publications” list is at route `/me/publications` (profile-linked).
- The `/saved` and `/archive` read-later routes use the same three-pane shell as `/read` (list column, detail with `EntryArticleEmbed`; saved/archive layouts keep `main` overflow-hidden; `saved/settings` scrolls inside the page). Archive is a sibling nav destination to Saved (sidebar on web, Lists on iOS)—not only an in-view toggle.
- LATR Link read-later: read-later provider selector removed on web+iOS—clients always use **L@tr Link** (no multi-provider picker; web `/saved/settings` redirects to `/saved`). Saved-link **list** uses **`GET /v1/latr/saves`** on latr-gateway (web + iOS; merged display rows built client-side from item records + preview fields). **Save** mutations use **latr-gateway** (`latrGatewayClient`, `LatrGatewayClient`); on iOS, **archive/unarchive/delete** write **`link.latr.saved.item`** direct to the viewer PDS via **`PDSRecordService`**/**`XRPCClient`** (not the Social Wire L@tr gateway triple-DPoP proxy). Lexicons in `packages/lexicons`, drift-tested against **`latr-packages`** git dep (`LATR_GATEWAY_SAVES_PATH`, record keys, gateway-client upstream DPoP). Official client auth uses server-side credentials: web via Railway Web `/api/latr-gateway` (`LATR_GATEWAY_*` on the Next.js service); iOS via Social Wire Gateway `/v1/latr/*` (`LATR_IOS_PROXY_*` on the Railway Gateway). iOS client uses `LatrGatewayEnvironment` with no shipped keys. Social Wire Gateway L@tr proxy needs dual DPoP (`DPoP` for gateway + `X-Latr-Gateway-DPoP` forwarded as outbound `DPoP` to L@tr; optional `X-ATProto-Upstream-DPoP` for PDS write-through)—one proof cannot serve both hops. Saved-link UI shows preview metadata from gateway/PDS enrichment (thumbnail, title, excerpt, site, author). Pocket/getpocket reader saved URLs must embed **`linkedWebUrl`**, not the Pocket reader wrapper (`savedLinkEmbedUrl`).
- Feed entry read/unread uses browser `the-social-wire.read-state.v1` (see `entryReadStateStorage`) and, when signed in, syncs first-read timestamps to `app.thesocialwire.entryReadState` on the user’s PDS (deterministic rkey = base32(SHA-256(entry AT-URI)), same scheme as L@tr item keys). Web and iOS dual-write read marks to AppView and PDS; re-sync on web tab visibility (`useCrossClientReadSync`) and iOS foreground (`syncCrossClientReadState`) by merging paginated PDS markers (canonical `app.thesocialwire.entryReadState` plus legacy `com.thesocialwire.entryReadState`, with legacy rkey cleanup on write) and refreshing AppView unread counts—iOS foreground sync should write through newly discovered PDS read marks to AppView before refreshing counts. OAuth scopes in `auth.ts` + `public/client-metadata.json` must include `repo:app.thesocialwire.entryReadState?...`; widening requires sign-out/in. With the entry list filtered to Unread, defer marking the open entry as read until the user navigates to another entry (avoids the row disappearing while still reading). Sidebar unread badges are scoped per publication, folder, and section, exclude read-later, and show the full count (no 99+ cap). iOS badge lookup must mirror web `lookupUnreadCountInMap` (`normalizeATRepoParam` equality only)—not `com.standard` lexicon aliases; do not combine optimistic count deltas with `effectivePublicationUnreadCount` (double-subtract)—refresh publication counts from AppView after mark read/unread. Article embed presentation (feed + read-later): prefer substantial record HTML inline, then oEmbed (`/api/oembed`), then sandboxed iframe for thin RSS-only summaries (`entryArticlePresentation`, `EntryArticleEmbed`); lock mode per article so refetches do not flip; Thin AppView entry detail sets `embedUrl` from `originalUrl` when only a summary exists.
